Prolog Rubik's Cube Solver

Status: complete enough • Date: 2026-01-29 • Tags: tau prolog, javascript, deep recursive search

I have no idea how to solve a Rubik's cube. I doubt I ever will. I do not have the patience. What I do know however, is Prolog! I just completed my non-procedural programming course in university, and want to show off a bit!

This is a Rubik's cube solver written in prolog and interpereted in javascript for the browser and interactability. It is not very good, but it was certainly fun to make. Right now it can only solve cubes (in a reasonable ammount of time) that are max 5-6 steps away from already being solved.

Summary

In order to interact with my prolog code, the cube needs some sort of representation. The UI serves as a way to input the state of the cube, and this state (a "sticker model") is then fed into Prolog via a Javascript translation layer.

Once the state is in prolog, it extracts "Cubies", or the physical peices that would make up a Rubik's cube. The data from the faces & the Cubies allows for validation of the cube's validity, if it is possible to solve. If it is possible, then the moves are computed in a sort of brute force manner by the Prolog solver.

The solver is an iteratively deepening search, meaning that it first tries a solution with 0 moves, then a solution with one move, then two, and so on. This may give you some insight into why it is so incredibly slow. It will find the optimal solution, but it will also do it at a snails pace.

Each iteration of the search compounds, so each step still pays the cost of all the previous ones... Not a very good solution, but it is a solution. The search size grows roughly like so:

  • depth 1: ~18
  • depth 2: ~18 × 12
  • depth 3: ~18 × 12²
  • depth 4: ~18 × 12³
  • . . .
  • depth 7: ~18 × 12⁶ = 53747712 searches.... yikes

I suggest you take a look at the Prolog code to understand what a weird language it is, and how much complexity there actually is to this "simple" implementation. Play around with the demo above (under "Links") and see for yourself how it works. I suggest using this website in its flat view if you dont have a Rubik's cube lying around.
